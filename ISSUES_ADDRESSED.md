# Issues from `akappner/MieleRESTServer` Addressed in `miele-local-server`

| Upstream Issue / PR | Problem in Upstream | Fix / Improvement in `miele-local-server` |
|---|---|---|
| **#1, #29** (DOP2 walker hangs / crashes / `numpy` dep) | Synchronous `requests` had no timeout; ESP32 EK057 modules stalled or dropped connections; empty `204` DOP2 responses returned `None` causing `TypeError`; `DOP2FileList.readFields()` missed `self`. | Async `aiohttp` with explicit 6–8s timeouts, configurable DOP2 throttling (`0.05s`) & bounded walk duration (`25s`), safe empty-response handling, fixed `DOP2FileList(self)`, JSON-safe tree caching in SQLite, clean HTTP `404`/`502` JSON errors instead of `500`, and zero `numpy` dependency. |
| **#27** (Oven H7264BP remote start & `ProgramID` & temps & connection reset) | `ProgramId` only covered laundry devices (`24` failed or collided on ovens); `Temperature` / `TargetTemperature` stayed in raw centi-degrees (`4000`, `-32768`); `/start` GET required `ProgramType == 2`; `ConnectionResetError` caused HTTP `500`. | Device-type-aware `ProgramID` decoding (`ProgramIdOven`, `ProgramIdDishwasher`, `ProgramIdCoffeeMaker`, `ProgramIdLaundry`); decoded Celsius floats (`CurrentTemperature`, `TargetTemperatureValue`) ignoring `-32768`; remote-start readiness checks `Status in (Programmed, WaitingToStart)` with `RemoteEnable`; `start_appliance` sends optional pre-wake `ProcessAction: 16`; `ClientError` returns clean `502`. |
| **#32** (Read fill levels, e.g. dishwasher salt / TwinDos / coffee) | No dedicated endpoint or UI for fill levels, alerts, or consumption metrics. | Added `GET /devices/{id}/consumables` and **Consumables & Alerts** tab in the Web UI: exposes `SignalInfo` / `SignalFailure` / `SignalDoor` flags and probes DOP2 notifications (`2/131`, `2/392`), failure list (`2/148`), TwinDos container sensors (`2/6193`), process energy/water (`2/6195`), and operating hours (`2/119`). |
| **#29, #31** (Provisioning HTTP `403 Forbidden`) | `provision-key.sh` failed silently or unclearly on factory-locked appliances (TEC/TWD dryers, G7xxx dishwashers). | Built-in LAN Commissioning in the Web UI tries HTTP & HTTPS (`MielePairing:Pairing`) and detects `403`, surfacing the exact Miele app link/unlink unlock instructions. |
| **#5, #16** (Docker binding, single-file bind mount, HA add-on, zero-block startup) | Container bound to `127.0.0.1`, exited without `/etc/MieleRESTServer.config`, and required bind-mounting a single file. | Binds to `0.0.0.0:5001`, persists everything in `/data/miele-local.db`, starts cleanly with 0 appliances so setup can be done in the Web UI, includes `HEALTHCHECK`, `docker-compose.yml`, `qnap-update.sh`, and multi-arch `home-assistant/` add-on files. |
| **#18** (OpenAPI spec, formatting, device interview) | Flask app had no OpenAPI schema, no linter/formatter config, and re-interrogated devices on every request. | Built on FastAPI + Pydantic (`/docs` OpenAPI), Ruff/Black config in `pyproject.toml`, SQLite device metadata + DOP2 capability interview on setup/startup, and adaptive async polling + SSE `/events`. |
| **#7, #11, #14, #15, #24, #28, #30** (Compatibility, naming, ProgramIDs) | Generic `"washer"` key confused oven owners; missing `HandWash` (178), `EU Eco` (190), and full 91-entry `DeviceType` enum. | Friendly `display_name` separate from `endpoint` slug, full `DeviceType` enum from `dop2rs`, and updated laundry/oven/dishwasher/coffee program tables. |
| **Crypto long-payload bug** (`MieleCrypto.py` `pad_body_str`) | Payloads > 64 bytes were not padded to a 16-byte AES-CBC block boundary (`" " * (64 - len)`), causing encryption `ValueError`. | Fixed `pad_body_str` to align any length to `max(64, ceil16(len))`. |
